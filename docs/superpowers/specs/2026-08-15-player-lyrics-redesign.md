# 飞牛音乐播放器与歌词页改造设计

## 1. 目标与范围

本次改造只调整手机端全屏播放器、歌词页、歌词设置和相关系统播放能力，不改变首页悬浮播放条、播放队列数据模型和现有播放引擎的职责边界。

视觉和交互以用户提供的华为音乐截图为参考，但使用飞牛音乐的真实歌曲、封面、歌词、音频格式和播放队列数据，并遵循项目现有 HarmonyOS 安全区、深浅色资源、系统图标和 HMRouter Dialog 规范。

## 2. 播放器封面页

播放器顶部保留左侧收起按钮和中间两页指示器。左侧按钮及右侧投播按钮均使用透明背景，只保留系统点击态。右上角由播放队列改为系统投播入口。

页面主体依次展示封面、歌曲名、歌手、进度条、时间与音频格式、五键播放控制。进度条上方不再显示当前歌词。

时间行布局为：左侧当前时间、中间真实音频格式、右侧总时长。格式优先读取 `MusicTrack.audioSpec.format`，为空时回退 `codec`，仍为空则隐藏中间标签，不固定写死 `FLAC`。

播放控制统一为一排五个按钮：循环模式、上一首、播放或暂停、下一首、播放队列。删除当前单独的循环、歌词、队列操作排。左右小按钮保持透明背景，中央播放按钮保留强调视觉。

背景从当前封面 `PixelMap` 提取主色和平均色，生成克制的深浅渐变，并叠加保证文字对比度的明暗遮罩。取色失败、无封面或封面加载中时，回退现有 base/dark 播放器背景资源。切歌时颜色使用短时渐变过渡，不闪白。

## 3. 歌词页状态机

歌词页顶部显示小封面、歌曲名和歌手，不显示收藏按钮。歌词页与封面页继续通过横向滑动和顶部页指示器切换。

歌词页包含两种视觉状态：

- 控制态：显示顶部歌曲信息、歌词列表、进度条和五键播放控制。
- 沉浸态：保留顶部歌曲信息和歌词列表，隐藏进度条及播放控制，右下角始终保留“词”按钮。

进入歌词页时先显示控制态。连续 5 秒没有有效操作后进入沉浸态。切歌、播放暂停、拖动进度、点击歌词 Seek、手动滚动歌词以及重新进入歌词页都会重新开始 5 秒计时。

沉浸态下，点击歌词内容左侧的空白交互区恢复控制态并重启计时。“词”按钮只打开歌词设置弹窗，不负责恢复播放控制。点击顶部收起或左右滑动仍按原播放器导航逻辑处理。

## 4. 歌词滚动与指定时间播放

正常播放时歌词自动跟随当前行，当前行使用主文字色和较高字重，前后歌词按距离逐级降低透明度。

用户开始手动上下滚动时进入预览状态，暂时停止自动跟随。列表中央附近的候选歌词行成为 Seek 目标，并在该行右侧显示胶囊按钮，内容为播放图标和该行时间，例如 `01:41`。

点击时间按钮后调用现有 `seekTo(timeMs)`，退出预览状态，恢复自动跟随，并重新开始 5 秒沉浸计时。用户停止滚动但没有点击按钮时，预览状态保持；播放进度继续变化，但列表不自动跳回当前播放行。切歌或离开歌词页时自动退出预览状态。

加载中、无歌词和读取失败状态继续使用现有数据状态。无歌词时不显示“从该时间播放”按钮；读取失败提供重试入口。

## 5. 歌词弹窗与系统歌词设置

点击右下角“词”按钮，通过 HMRouter Dialog 打开覆盖底导航层级的歌词底部弹窗。弹窗标题为“歌词”，包含“状态栏歌词”入口，关闭按钮使用系统图标，不使用文本字符。

状态栏歌词设置页参考截图实现以下项目：

- 状态栏歌词总开关。
- 单行或双行展示。
- 居左或居中对齐。
- 左右位置、上下位置、显示宽度和背板透明度调节。
- 字号调节和歌词颜色选择。

设置值使用本地 Preferences 持久化，并维护深浅色下的可读性。颜色使用色块控件，不用文字按钮模拟。

系统实现优先使用 API 26 `AVSession` 的桌面歌词能力：先调用 `avSession.isDesktopLyricSupported()`，支持时通过当前会话的 `enableDesktopLyric()`、`setDesktopLyricVisible()` 和状态回调同步开关。歌词文本继续通过现有 `AVMetadata.lyric` 发送给系统。

系统返回 `6600111` 时表示设备不支持；返回 `6600110` 时表示当前应用会话尚未启用。两者都要转成明确中文提示并回滚开关状态。系统桌面歌词目前只公开锁定状态，单行、位置、宽度、背景、字号和颜色等细节没有对应公开 API，因此这些样式项只在系统确认支持相应扩展前启用；不能把本地设置伪装成已经影响系统状态栏。

## 6. 投播

右上角投播入口复用当前 `AVSession`，基于系统 `AVCast` 能力打开系统设备选择或投播控制。没有可用设备、模拟器不支持或系统能力缺失时显示中文状态提示，不跳转空白页面，也不打开播放队列。

投播状态变化需要同步到播放器按钮的可访问描述。投播失败不应中断本机播放。

## 7. 后台播放

项目现有 `EntryAbility` 已声明 `backgroundModes: ["audioPlayback"]` 和 `ohos.permission.KEEP_BACKGROUND_RUNNING`，`AvSessionBridge` 也已调用 `setBackgroundPlayMode(ENABLE_BACKGROUND_PLAY)`。本次不重复添加权限，而是补齐并验证播放生命周期：

- 进入后台时保存会话，但不释放 `AVPlayer` 或停用正在播放的 `AVSession`。
- 暂停后仍保留媒体中心会话；用户主动关闭播放队列时才释放播放资源。
- 锁屏、熄屏和退后台后仍可连续播放、切歌、暂停和恢复。
- 媒体中心、锁屏控制和耳机按键继续调用同一 `MusicPlaybackController`。
- 进程被系统回收后，下次启动恢复队列、当前歌曲和已持久化进度，但不未经用户操作自动发声。

如果真机验证证明 `AVSession` 的后台模式不足以维持当前系统版本的播放，再增加 `backgroundTaskManager` 音频长时任务；在没有验证证据前不叠加第二套常驻通知和生命周期。

## 8. 组件与状态边界

动态歌词列表、播放控制、格式标签、沉浸状态和取色结果不得写入 `@Builder`。拆分为 `@ComponentV2` 子组件或直接放在组件 `build()` 中，通过真实 `@Param`、`@Local` 和 `@Trace` 状态驱动刷新。

建议边界：

- `PlayerArtworkPage`：封面、歌曲信息、进度与五键控制。
- `PlayerLyricPage`：歌词状态机、滚动预览和 Seek 目标。
- `PlayerControlRow`：五键控制的统一布局。
- `PlayerDynamicBackground`：封面取色与降级背景。
- `LyricsSheet`：歌词底部弹窗。
- `DesktopLyricSettingsPage`：系统能力状态和本地设置。
- `AvSessionBridge`：投播、桌面歌词和后台会话接口。

不得使用无业务含义的刷新版本号、随机 key 或时间戳强制 UI 更新。

## 9. 验证矩阵

构建验证使用 DevEco Studio 3 API 26 SDK，至少通过 ArkTS 编译和 HAP 打包。

模拟器验证：封面页布局、透明顶部按钮、真实格式标签、五键控制、歌词页切换、5 秒沉浸、空白区恢复、手动滚动预览、指定时间 Seek、底部弹窗、深浅色和不支持系统能力时的降级提示。

真机验证：封面动态取色、投播设备发现、系统桌面歌词支持状态、退后台持续播放、锁屏和熄屏播放、媒体中心控制、耳机控制、切歌、Seek，以及应用被回收后的会话恢复。

模拟器无法证明投播、系统桌面歌词或后台保活。最终报告必须把构建、模拟器和真机证据分开记录。
