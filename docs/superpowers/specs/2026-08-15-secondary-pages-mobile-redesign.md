# 飞牛音乐二级页面移动端重设计

## 目标

在不改变现有接口、路由和播放能力的前提下，把飞牛音乐 Web 端的真实内容结构重新组织为 HarmonyOS 手机端二级页面。页面不照搬 Web 端侧栏、桌面表格和公共标题栏，而是保留其内容语义、封面资源、数量信息、操作优先级和页面背景氛围。

本轮只改手机布局。播放器主体和首页框架保持现状，悬浮播放条继续由现有全局壳层承载。

## 已确认方向

采用“内容类型差异化”的统一框架：

- 专辑集合页使用双列封面网格。
- 歌手集合页使用头像列表，突出歌曲数和专辑数。
- 风格集合页使用双列主题卡片，保留 Web 端唱片视觉语义。
- 音乐库、收藏、最近播放和详情页使用高密度歌曲列表。
- 收藏、最近播放、专辑详情、歌手详情和风格详情吸收 Web 端的取色背景与封面氛围，但不使用桌面端大面积横向布局。
- 搜索页保留独立全屏页面和 Chip 切换，歌曲、专辑、歌手分别使用对应的移动端结果样式。

## 页面壳层

所有二级页继续使用 `HdsNavDestination`，统一隐藏默认标题栏，由公共移动端壳层处理：

- 顶部包含状态栏安全区、透明渐隐 ActionBar、返回按钮、标题和可选操作按钮。
- ActionBar 从首屏开始透明覆盖内容，滚动内容从其背后经过；顶部材质只做渐隐和模糊，不出现整块不透明底板。
- 页面内容只分配一次顶部安全区，不在页面内重复叠加 `statusBarHeight`。
- 固定内容左右外边距为 `14vp`；横向滚动和网格容器可以铺满画布，但首项仍与 `14vp` 基线对齐。
- 底部为现有悬浮播放条预留动态空间，列表最后一项使用 `bottomInset`，避免歌曲或分页状态被遮挡。
- 深浅色模式分别维护颜色资源。品牌强调色继续使用飞牛音乐红色，系统材质、文字和表面色使用语义资源。

## 集合页

### 专辑

- 顶部只显示“专辑”和总数，不再为每一张专辑绘制整行大卡片。
- 主体为双列自适应网格，封面保持 1:1，圆角使用 `FnUI`/`FnMusicUI` 的保守档位。
- 每项显示专辑名、歌手和歌曲数；无封面时使用项目已有音乐字体图标或真实资源占位。
- 封面右下角可在按压或聚焦状态显示播放按钮；点击主体进入专辑详情，点击播放只播放该专辑。
- 顶部操作提供排序入口。分页沿用现有运行时状态，在网格底部显示加载、失败重试和已加载数量。

### 歌手

- 使用紧凑头像列表，而不是专辑同款网格。
- 头像为圆形，正文显示歌手名，副文案显示“歌曲数 · 专辑数”。
- 列表不再给每一行单独套重色卡片；同组使用轻量分隔和按压材质。
- 支持现有分页状态，空态、加载态和错误态使用统一组件。

### 风格

- 使用双列主题卡片，卡片高度低于专辑封面。
- 复用 Web 端唱片/纹理语义，显示风格名和歌曲数；没有封面时使用统一唱片资源，不用临时文本符号。
- 每种风格允许基于名称稳定映射一组背景色，但必须来自深浅色资源，不在页面内硬编码随机颜色。

### 音乐库

- 不使用大 Hero 卡，首屏优先展示歌曲。
- 标题区显示总歌曲数，并提供“随机漫游”和排序入口。
- 歌曲行显示封面、歌曲名、歌手、专辑、时长和更多操作；格式信息压缩为轻量标签，只在有值时显示。
- 分页沿用 `AppRuntime.loadMoreTracks()`，加载更多时不改变列表宽度和行高。

## 详情与歌曲集合页

### 专辑详情

- 顶部 Hero 使用真实专辑封面、专辑名、歌手、发行年份和歌曲数。
- 主操作为播放，次操作为随机/排序或更多；按钮数量根据真实能力显示，不放空入口。
- Hero 背景从封面主色生成柔和渐变，正文区域逐渐过渡到页面背景。
- 歌曲列表不再逐行套独立卡片，使用连续列表、轻量分隔和统一按压反馈。

### 歌手详情

- 使用圆形歌手头像、歌手名、歌曲数和专辑数。
- 提供“歌曲 / 专辑”Chip 切换。歌曲来自现有 `artistTracks`；专辑从已加载专辑中按歌手标识或名称筛选，数据不足时显示明确空态。
- 歌曲页为连续列表，专辑页为双列网格。

### 风格详情

- Hero 保留 Web 端唱片视觉，显示风格名、歌曲数和播放全部。
- 下方直接显示歌曲列表，不制造不存在的二级分类。

### 收藏与最近播放

- 保留 Web 端红色收藏背景和绿色最近播放背景，但降低移动端首屏 Hero 高度。
- Hero 显示对应图形、标题、总数、播放全部；收藏额外提供随机播放，最近播放只显示真实可用操作。
- 空收藏页仍保留 Hero，在列表区域显示空态，不让整页只剩一个居中的占位图。

### 自建歌单

- 沿用歌曲集合页壳层，Hero 显示歌单名、描述和歌曲数。
- 右上角更多菜单保留编辑和删除能力；曲目行继续支持从歌单移除。

## 搜索页

- 搜索栏固定在顶部安全区下方，返回按钮和输入框处于同一 ActionBar 层级。
- 输入为空时显示最近搜索；结果出现后显示“歌曲 / 专辑 / 歌手”Chip。
- 歌曲结果使用高密度歌曲列表，专辑结果使用双列封面网格，歌手结果使用头像列表。
- 切换 Chip 时保留查询词，不重置滚动壳层；加载、错误和空态不改变顶部结构。
- 继续使用 400ms 防抖，提交搜索时立即执行。

## 组件边界

新增或重构的动态 UI 必须使用 `@ComponentV2`，禁止把接口、VM、`@Trace`、`@Local` 或 `@Param` 驱动内容放进 `@Builder`。

组件边界：

- `MusicSecondaryScaffold`：安全区、渐隐 ActionBar、背景和底部避让。
- `AlbumGrid` / `AlbumGridItem`：专辑集合和搜索专辑结果复用。
- `ArtistList` / `ArtistListItem`：歌手集合和搜索歌手结果复用。
- `GenreGrid` / `GenreGridItem`：风格集合。
- `MusicDetailHero`：专辑、歌手、风格、收藏、最近和歌单的可配置 Hero。
- `DenseTrackList` / `DenseTrackRow`：音乐库、搜索和各详情页复用。
- `CatalogPagingFooter`：保留现有分页语义，统一视觉。

组件只接收展示所需的数据和事件，不直接持有导航或播放业务。导航、接口请求、播放队列和菜单仍由 `AppShell` 与 `AppRuntime` 负责。

## 数据流和行为

- 集合页继续消费 `AppRuntime.state()` 中的专辑、歌手、风格、歌曲和分页字段。
- 专辑、歌手、风格、收藏、最近和歌单详情继续使用现有 `openAlbum`、`openArtist`、`openGenre`、`openCollection` 和 `openPlaylist` 流程。
- 播放全部、随机播放、专辑播放和单曲播放继续走现有 `playTracks`、`playAlbum` 和 `playCollection`。
- 漫游仍是播放模式，不新增漫游详情页；漫游卡片主体保持不可点击，仅播放按钮启动连续漫游。
- 悬浮播放条和播放器的一镜到底转场不在本轮重写，只验证新页面底部避让、点击区域和转场入口不回归。

## 状态矩阵

每类页面至少验证：

- 正常数据、长标题、缺失封面、数量为零。
- 首次加载、分页加载、分页失败重试、接口失败、空态。
- 浅色、深色。
- 无悬浮播放条、有悬浮播放条。
- 顶部初始状态、列表滚动后 ActionBar 渐隐材质状态。
- 按压、禁用、聚焦和加载中的按钮状态。

## 实施批次

1. 公共壳层、公共列表/网格组件、专辑集合页和专辑详情页。
2. 歌手集合/详情、风格集合/详情。
3. 音乐库、收藏、最近播放和自建歌单详情。
4. 搜索页三类结果、空态和分页视觉统一。
5. 深浅色、模拟器与真机状态矩阵回归，运行 `scripts/ui-size-guard.sh` 和构建检查。

每一批完成后都必须在模拟器打开真实页面截图对照 Web 端内容结构，不能只以构建成功作为视觉验收。

## 验收标准

- 二级页不再统一呈现为“一行一张重色卡片”。
- Web 端的重要字段和操作没有丢失，桌面表格字段在手机上被合理折叠。
- 专辑、歌手、风格、歌曲列表在首屏即可通过视觉形态区分。
- 顶部透明、安全区、滚动材质和底部悬浮播放条在所有二级页一致。
- 深色模式不出现发绿卡片，浅色模式不依赖纯白大底板。
- 真实数据、分页、播放、更多菜单、收藏和导航行为保持可用。
